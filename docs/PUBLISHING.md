# 工具上架與下架規範

> 狀態：定案。最後更新：2026-10-25。這是 Teacher Hub **上架、改狀態、下架**的唯一流程文件；與 [MAINTENANCE.md](../MAINTENANCE.md) 第 5、6 節重疊處以本文件為準，MAINTENANCE 的其餘規則（授權、版權、自動同步、卡片導覽硬性要求）仍然有效。長相與元件見 [docs/design/DESIGN.md](design/DESIGN.md)。

**給 AI 與協作者：** 上架或下架任何工具之前先讀本文件與 MAINTENANCE.md。**沒有擁有者（derliang）在對話中明確同意，不得上架、不得改狀態、不得下架。** 不得因為搜尋到某個 repo 就自行收錄。

## 1. 先分區：這個工具放哪一區

首頁只有兩區。用下面三個問題判斷，順序不能換：

1. **使用者是一個人，還是一群人各自操作同一份資料？** 一群人（例如同學各自用手機點餐）而且沒有後端，不得上架（MAINTENANCE 第 17 節）。
2. **工具在 GitHub Pages 上能直接完整運作嗎？** 能，而且資料只存使用者自己的裝置或自己的雲端硬碟 → 「立即可用」區。
3. **工具要在老師自己的 Google 帳號下跑 GAS（Apps Script）嗎？** 是 → 「GAS 部署」區，走自助部署平台。

| 區 | 條件 | 卡片點下去會去哪裡 |
|---|---|---|
| **立即可用**（線上直接執行） | 作者自己開發、已公開、GitHub Pages 有可操作的正式頁面、單人使用 | 直接開啟該工具的 GitHub Pages 網址（外部，↗） |
| **GAS 部署** | 需要 GAS 後端；老師各自安裝到自己的 Google 帳號 | 站內自助部署平台 `/deploy/?product=<產品 id>`；未通過驗收前沒有連結 |

## 2. 狀態與生命週期

```
候選 ──→ 施工中・可預覽 ──→ （Beta）──→ 即開即用
  │            │               │            │
  └────────────┴───────────────┴────────────┴──→ 下架
```

| 狀態 | 首頁呈現 | 進入條件 | 誰決定 |
|---|---|---|---|
| 候選 | 虛線候選卡，無連結，寫「敬請期待」，**GAS 區專用** | 擁有者指定，且是 GAS 工具 | 擁有者 |
| 施工中・可預覽 | 可點，標「施工中」，進入預覽或平台入口 | 有可展示的頁面，且頁面明確寫尚未開放 | 擁有者 |
| Beta | 可點，標「Beta」，顯示版本與發布日 | 功能可用，但仍在試用調整 | 擁有者 |
| 即開即用 | 可點，標「即開即用」，顯示版本與發布日 | 通過第 3 節檢查清單 | 擁有者 |
| 已下架 | **不在首頁出現** | 見第 4 節 | 擁有者 |

「立即可用」區的卡片只能是 Beta 或即開即用；「候選」與「施工中」只出現在 GAS 區。

**未完成的 GAS 工具只有兩種合法呈現**（細則與預覽頁規則見 [DESIGN.md 5.1](design/DESIGN.md)）：
- **候選**：不可點的虛線卡，沒有任何說明頁。
- **施工中・可預覽**：可點的卡，連到 `gas/<工具 id>/` 預覽頁（過渡期的平時成績連舊原型）。預覽頁必須有「施工中」橫幅、沒有任何按鈕或登入、有「返回 GAS 部署區」。候選要變可點，卡片與預覽頁在同一個 PR 內完成。

驗收前不得用其他樣子暗示工具能用；驗收通過並由擁有者說「發佈網頁」後，才把卡片改連 `deploy/?product=<id>`，並刪除預覽頁。

## 3. 上架

### 3.0 所有工具共同要做

- [ ] 擁有者在對話中明確指定並同意收錄這個工具。
- [ ] 回答第 1 節三個問題，並把分區與理由寫進 CHANGELOG。
- [ ] 卡片內容備齊（見 3.3）。
- [ ] 版本與日期依 MAINTENANCE 第 4 節更新：新增工具升 MINOR；同步改 `site.json`、`CHANGELOG.md`、`index.html` 頁尾備援文字，三者一致。日期用台灣日期。
- [ ] **新增或改動頁面時：先登記**在 `docs/design/pages.json` 與 `docs/design/PAGES.md`，並有對應模擬頁（流程見 PAGES.md 第 6 節）。
- [ ] **`python scripts/check_design.py` 全部通過**（檢查 tokens、導覽、麵包屑、件數、版本一致等；上架與下架一定會改到首頁，所以一定要跑）。
- [ ] 人工檢查（自動檢查看不到的）：手機（390）、iPad（820）、桌機（1280）沒有橫向捲動、淺深色都看過、鍵盤 Tab 可用；搜尋找得到新卡片，卡片總數與兩區件數標示正確。結果寫進 PR 說明。
- [ ] 頁尾版權句、授權連結、`LICENSE.md` 沒被動到（MAINTENANCE 第 18 節）。
- [ ] 保留原有卡片與歷史 commit，不覆蓋他人更動。
- [ ] 經擁有者審核後才合併到 `main`；合併後確認 GitHub Pages 已發布、首頁能開、**全部**卡片可用。提交成功不等於 Pages 部署成功。

### 3.1 「立即可用」區（線上直接執行）

- [ ] 原 repo 已公開，GitHub Pages 有正式可操作頁面；**親自開啟正式網址驗證**，不用 repo 網址代替。
- [ ] 整張卡片是一個 `<a href>`，直接指向 GitHub Pages 操作頁，不經介紹頁，不用 iframe，不改原工具 repo。
- [ ] 版本資料：在 `tools.json` 加一筆（`id`、`version`、`releaseDate`、`source`、`versionJson`、`dateEvidence`），卡片 `.app-meta` 加 `data-tool="<id>"`，（`scripts/sync_tool_releases.py` 以 `tools.json` 為核准名單，所以只要加進 `tools.json` 就會被自動同步；MAINTENANCE 第 8、9 節）。工具沒有 `version.json` 時先經擁有者同意再擴充腳本，不得修改原工具 repo。
- [ ] 版本與發布日要有可靠來源，不得填今天日期或憑空推測（MAINTENANCE 第 8 節）。查證不到就維持不上架。
- [ ] 版本顯示用 `v版本｜發布：YYYY-MM-DD`，指該工具本身，不是 Teacher Hub 的日期。

### 3.2 「GAS 部署」區（自助部署）

GAS 工具的**後端**（授權閘門、產品 manifest、正式版發布包）與其規則在私人 repo `derliang/gas-deploy-helper`；Teacher Hub 這裡放卡片與**前端介面**（`deploy/`，原始碼在本 repo）。**「push git」是提交到私人 repo（後端）；「發佈網頁」才是更新 teacher-hub（前端），兩者不可互換。**

1. [ ] 擁有者核准這個產品進入自助部署，且已回答第 1 節（多人使用必須有 GAS 或線上資料庫後端）。
2. [ ] 在 `gas-deploy-helper` 的 `selfservice/gate/Gate_10_products.gs` 新增產品 manifest（`id`、正式版 repo、受管理檔案、版號規則、Web App 設定、首次授權函式、安裝完成後老師要自己做的步驟）。通用核心不得寫死單一產品名稱。
3. [ ] 在管理頁匯入並審核正式版：檢查通過，並**表態是否涉及資料遷移**。涉及或不確定的版本只開放首次安裝，自助更新會被擋。
4. [ ] 管理員逐一授權教師（教師 × 產品逐項勾選）。
5. [ ] 通過真實 Google 驗收：個人 Gmail 被拒、未授權教師被拒、首次安裝、在編輯器授權後網址可開、同網址更新且網址不變、`hd` 不符被拒。**驗收前不得宣稱可用。**
6. [ ] 首頁卡片依狀態呈現：驗收前一律是「候選」或「施工中・可預覽」，不連到尚未開放的功能；施工中的卡片連到 `gas/<id>/` 預覽頁（規則見 DESIGN.md 5.1，並登記在 `pages.json`）；驗收通過、且擁有者說「發佈網頁」後，卡片才連到 `deploy/?product=<id>` 並改標「即開即用」，同時刪除預覽頁。
6a. [ ] `deploy/` 前端的任何改動，要先通過 `python scripts/check_design.py` 與 `node --test scripts/test_deploy_frontend.mjs scripts/test_wizard_contract.mjs`（樣式必須使用 `tokens.css`），再合併。`deploy/config.json` 的 `gateUrl` 是**上線開關**：留空時頁面只顯示「平台尚未開放」；通過第 5 項真實驗收、且擁有者說「發佈網頁」後才填入閘門網址（PAGES.md 第 7 節）。
7. [ ] `deploy/` 是公開檔案，不得含 token、OAuth Client Secret、私鑰、Email 名單（`scripts/test_deploy_frontend.mjs` 內建掃描，會在提交前擋下）。
8. [ ] GAS 工具不列入 `tools.json` 的版本追蹤：每位老師安裝的版本不同，正式版與日期顯示在自助部署頁內。

### 3.3 卡片內容欄位

| 欄位 | 規則 |
|---|---|
| 分類（tag） | 兩到四個字，例如「座位安排」 |
| 名稱 | 與工具本身一致，不加 emoji |
| 狀態 | 見第 2 節 |
| 一句話說明 | 一句，講它幫老師做什麼；與原工具介紹一致，不誇大 |
| 特色 | 三到四個該工具**已有**的功能詞，用「·」分隔；超過就寫「另有 N 項」 |
| 版本｜發布日期 | 僅「立即可用」區，來源是 `tools.json` |
| 圖片 | `images/cards/<id>.svg`，4:3、不含真實學生個資、替代文字寫工具名稱 |
| 連結 | 整張卡片一個連結，見 3.1、3.2 |

## 4. 下架

### 4.1 什麼時候下架

- 擁有者決定停止提供。
- 發現工具不符第 1 節（例如多人使用卻沒有後端；午餐小幫手網頁版 2026-10-24 即為此例）。
- 原工具無法再維護、網址失效，或出現無法排除的資料或安全問題。

出現問題時，**先下架再修，不要讓使用者繼續用可能出錯的工具。**

### 4.2 步驟

1. [ ] 取得擁有者的明確同意（在對話中）。
2. [ ] 決定下架後的去處：
   - 還會再做 GAS 版 → 改回「候選」佔位卡（GAS 區）。
   - 不再提供 → 直接移除卡片。
3. [ ] 「立即可用」區的工具：從 `tools.json` 移除該筆（自動同步名單隨之更新），並移除卡片 `data-tool`。
4. [ ] GAS 區的工具：卡片改回「候選」或「施工中」（候選不可有連結；若改回候選，同時刪除 `gas/<id>/` 預覽頁並移除 `pages.json` 對應）；在自助部署平台停用該產品的授權或安裝入口。**不刪、不改老師已經安裝的 GAS**，已安裝的系統照常可用。
5. [ ] 版本與紀錄：升 MINOR，同步 `site.json`、`CHANGELOG.md`、`index.html` 備援文字。CHANGELOG 寫清楚下架原因、卡片去向、公開 repo 是否保留。
6. [ ] 在 MAINTENANCE.md 增加一節說明來龍去脈與新規則（比照第 17 節的寫法），避免下一個對話重蹈覆轍。
7. [ ] **不刪公開 repo 與 GitHub Pages**，只從入口移除，供日後參考；要刪除須另行取得擁有者同意。
8. [ ] 檢查：`python scripts/check_design.py` 全部通過；卡片總數與兩區件數標示正確、搜尋不再找到該工具、其他卡片與連結沒有退化。經擁有者審核後合併 `main`，並確認 Pages 已發布。

### 4.3 重新上架

視為新上架，從第 3 節重走一遍，並在 CHANGELOG 說明為什麼現在符合條件。

## 5. 給新對話的速查

| 你被要求 | 先做 |
|---|---|
| 新增一個工具 | 讀本文件第 1、3 節，先問擁有者「一個人用還是一群人」 |
| 改某張卡片的文字或狀態 | 讀 DESIGN.md 第 4 節狀態標籤與文案語氣，狀態升級要有第 2 節的進入條件 |
| 下架 | 讀第 4 節，先停手，確認去處與是否保留公開 repo |
| 改頁面外觀 | 讀 DESIGN.md，沿用 tokens，不要寫死色碼；完成後跑 `python scripts/check_design.py` |
| 新增任何頁面 | 讀 PAGES.md 第 6 節：先登記、先有模擬頁、再實作、跑檢查、人工檢查 |
| 做出「施工中」的 GAS 工具頁 | 讀 DESIGN.md 5.1：預覽頁不得有按鈕或登入 |
| 說「push git」 | 指 `gas-deploy-helper`（私人、後端）的提交，不是 teacher-hub |
| 說「發佈網頁」 | 指更新公開的 teacher-hub；合併 `main` 前仍要確認 |
