# Teacher Hub：設計規範

> 狀態：定案。最後更新：2026-10-25。改任何頁面、版面、元件、樣式前先讀這份。要偏離，先更新本文件並取得擁有者確認。

- 定案的模擬頁：`docs/design/mockups/`（首頁、自助部署、部署管理）。用瀏覽器直接開，可縮放視窗看三種裝置寬度。
- 頁面清冊、層級、必備導覽與防走樣機制：[PAGES.md](PAGES.md)（機器可讀版 [pages.json](pages.json)）。
- 唯一的 token 來源：[tokens.css](tokens.css)。每頁的 token 都要與它相同。
- 自動檢查：`python scripts/check_design.py`，改到頁面的 PR 都要先跑過。
- 上架與下架流程：[docs/PUBLISHING.md](../PUBLISHING.md)。
- 站務與交接規則：[MAINTENANCE.md](../../MAINTENANCE.md)。本文件只管「長什麼樣」，不改變 MAINTENANCE 的功能與授權規則。
- 範圍：視覺、版面、導覽、文案語氣。功能邏輯（卡片整張可點、搜尋、版本同步、自助部署的安裝與更新規則）不在本次改動內。

## 1. 設計原則

1. **學院編輯風，不是商品目錄。** 象牙底、深海軍藍、黃銅金只用在標示與細線，標題用襯線字。理由：這是給學校老師的工具，要有質感也要安靜。
2. **先分流，再選工具。** 首頁第一屏就說清楚「立即可用」與「GAS 部署」兩區的差別。理由：使用者不該先讀完七張卡片才知道哪些能直接用。
3. **一頁只做一件事。** 自助部署用精靈，一步一個決定；有風險的步驟要勾選確認。理由：老師不是技術人員，出錯的代價是動到自己的系統。
4. **狀態要誠實。** 還沒做完、還沒驗收的東西一律標「施工中」或「候選」，不用漂亮的卡片暗示它能用。理由：與 MAINTENANCE 第 13、17 節一致，不可宣稱未完成的功能。
5. **任何位置都能回頭。** 每個頁面都有頂端導覽、所在區段標示、麵包屑或返回首頁。理由：不讓人迷路。

## 2. Tokens

所有顏色與字型都用 CSS 變數，不在元件裡寫死色碼。變數的唯一來源是 [tokens.css](tokens.css)；實作時把它的三個區塊（`:root`、深色 media、深色 `data-theme`）原樣放進頁面，`check_design.py` 會逐頁核對，值不同或多出規範沒有的 token 都會失敗。要改 token，先改 `tokens.css` 與下表，再同步所有頁面。

### 字型

| 用途 | 字型 | 字級／行高 | 字重 |
|---|---|---|---|
| 標題（h1、h2、h3、數字） | `Noto Serif TC`，備援 `Songti TC`、`PMingLiU`、serif | 首頁 h1：手機 34／平板 44／桌機 56，行高 1.25；h2：26／桌機 32；卡片 h3：21–22；皆用 `text-wrap: balance` | 700 |
| 內文與介面 | `Noto Sans TC`，備援 `PingFang TC`、`Microsoft JhengHei`、system-ui | 15，行高 1.7；說明 14.5；輔助 12.5–13 | 400／500／700 |
| 網址、版本、雜湊 | 系統等寬字 | 12.5 | 400 |

Google Fonts 載入：`Noto Sans TC` 400、500、700 與 `Noto Serif TC` 600、700，`display=swap`。小標用字距 `.14em–.24em`；數字欄位用 `font-variant-numeric: tabular-nums`。

### 間距、圓角、陰影、動態

- 圓角只有 **3px（按鈕、輸入）與 4px（卡片、面板）**，不使用大圓角，也不用膠囊形標籤。
- 間距用 4 的倍數，並排元素一律用 flex 或 grid 加 `gap`。
- 陰影只出現在可點卡片與首頁兩扇門的 hover（`0 16px 28px -20px var(--shadow)`），其他元件不加陰影，用 1px 外框區隔。
- 動態：可點卡片與兩扇門 hover（以及鍵盤聚焦）上移 3px、箭頭右移 3px，時間 .2s。`prefers-reduced-motion` 時全部關閉。不做進場動畫。

## 3. 版面與斷點

| 範圍 | 欄數與導覽 |
|---|---|
| 手機 < 600 | 單欄。頂端：品牌加搜尋鈕，第二列是「立即可用／GAS 部署」分段切換（各 44px 高）。左右留白 20px。 |
| 平板 600–1023（iPad 820 為基準） | 兩區都是單欄橫列（圖 230px 在左）。兩扇門並排。導覽改為單列：品牌、兩個區段連結、搜尋欄。左右留白 36px。 |
| 桌機 ≥ 1024 | 「立即可用」兩欄橫列（奇數張時最後一張跨整列）、GAS 區單欄列表。左右留白 48px。 |

- 內容最大寬度 1160px，置中。自助部署頁（精靈）最大 960px。管理頁用 1160px。
- 精靈在容器寬 ≥ 760px 時左側顯示步驟軌（200px），小於時改成頂部進度條。
- 頂端導覽列固定在頁面頂端（`position: sticky`，含安全區），標出目前所在區段。進入自助部署、管理頁時，「GAS 部署」為目前項目。
- 不得出現橫向捲動；只有表格可以在自己的容器內橫向捲動。

## 4. 元件規則

通用：點擊區至少 44px 高；焦點框 2px `--brass-line`，外移 2px；連結與按鈕的顏色都走 token，不出現瀏覽器預設藍。

| 元件 | 用途與規則 |
|---|---|
| **頂端導覽** | 品牌（深藍方塊加襯線 T、黃銅底線）、兩個區段連結（含件數）、搜尋（僅首頁）。已登入的自助部署頁，搜尋換成帳號與登出。 |
| **麵包屑** | 自助部署與管理頁必備：`Teacher Hub 首頁 › GAS 部署 › …`。最後一項是目前頁，不可點。 |
| **兩扇門** | 首頁第一屏的兩個入口。左（立即可用）深藍底，右（GAS 部署）紙面底加黃銅細框。各含一句說明與件數，點擊跳到該區。GAS 那扇在平台未通過驗收前標「施工中」。**互動回饋（必備，滑鼠移上與鍵盤聚焦相同）**：外框變色（深藍那扇變黃銅細線色 `--brass-line`，紙面那扇變深一階的黃銅色 `--brass`）、上移 3px、加卡片同款陰影、「前往這一區」的箭頭右移 3px。兩扇門都固定有 1px 外框（深藍那扇的外框與底色同色），所以變色不會讓版面位移。 |
| **區段標題** | 黃銅小標（左側 28px 細線）＋襯線 h2＋一到兩句說明；桌機右側顯示件數。GAS 區底色為 `--sunk`。 |
| **工具卡（橫列）** | 整張是一個 `<a>`，一次點擊開啟工具。左圖右文：圖片、分類、狀態標籤、名稱、一句話說明、特色（用「·」分隔的文字，不做膠囊）、底部列放「版本｜發布日期」與「開啟使用」。手機縮圖 104px 方形，≥ 600 為 230px、4:3。不可連到程式碼頁或介紹頁。 |
| **候選卡** | `<article>`，虛線外框、透明底、圖片轉灰；沒有連結，底部寫「敬請期待」。 |
| **狀態標籤** | 見下表。方角 2px，字 12.5px 粗體。 |
| **步驟條（首頁 GAS 區）** | 四步：登入、選首次安裝或更新、勾選確認、首次安裝後到編輯器授權。這是真實順序，才可用編號。 |
| **精靈** | 左軌（目前項目深藍左線、已完成黃銅左線加勾）、右側一次一件事。每一步底部放「上一步」（外框）與主動作（實心）。有風險的步驟先勾選確認，按鈕才可按。 |
| **進度列表** | 安裝與更新執行時使用：已完成（綠勾）、進行中（黃銅圈、粗體）、等待（灰點）、**失敗（紅圈、紅色粗體字，下方接一則 bad 訊息）**。失敗要停在該步，後面的步驟維持等待，不可繼續。模擬頁有失敗畫面。 |
| **危險操作按鈕** | `.btn.danger`：透明底、`--bad` 文字與外框。只用於停用、解除綁定、刪除等不可逆或影響他人的操作；不得用實心紅底；一樣 44px 高。 |
| **產品插圖** | 自助部署頁的產品卡使用該產品在首頁的同一張插畫（`images/cards/<檔名>.svg`）；沒有插畫就不顯示縮圖，**不用 emoji 或符號代替**。 |
| **狀態橫幅（banner）** | 預覽頁與施工中頁必備。黃銅淡底、黃銅外框、菱形標記，第一個字寫狀態（「施工中」「候選」）。放在標題下方，不可省略。 |
| **訊息（notice）** | 四種：info、warn、bad、ok。底色用對應的 soft token，文字用對應語意色，不依賴 emoji。 |
| **表單** | 輸入框 46px 高，標籤在上方粗體，提示在下方 13px。勾選框 22px，用 `accent-color: var(--primary)`。 |
| **表格（管理頁）** | 外框 4px，欄標 12.5px 字距，窄螢幕在自己的容器內橫向捲動（最小寬 600px）。 |
| **頁尾** | 只有一個，結構固定為：**品牌列**（`.fhead`：左品牌名、右「回到頂端 ↑」，窄螢幕也在同一列，**「回到頂端」不可單獨成列**）→ 一句說明（`.fnote`）→ 細線 → **法律列**（`.flegal`：單一版權句與授權說明連結；首頁另在同列靠右放「首頁版本與更新日期」，窄螢幕自動換行）。不可另加第二個頁尾（MAINTENANCE 第 18 節）。 |

### 狀態標籤

| 標籤 | 意義 | 出現位置 |
|---|---|---|
| 即開即用 | 正式、點開就能用 | 「立即可用」區 |
| Beta | 可用，但仍在試用調整 | 「立即可用」區 |
| 施工中・可預覽 | 入口已開，功能尚未開放 | GAS 區 |
| 候選 | 規劃中，沒有入口 | GAS 區 |
| 已核准・目前正式版／待審核／安裝未完成／有新版 | 自助部署與管理頁內的版本狀態 | /deploy/ 與 /deploy/admin/ |

「已下架」不在畫面上顯示，下架的工具直接移出首頁（流程見 PUBLISHING.md）。

## 5. 頁面規則

| 頁面 | 用途與區塊順序 | 模擬頁 |
|---|---|---|
| **首頁**（`/`） | 導覽 → 標題與一句話 → 兩扇門 → 「立即可用」區 → 「GAS 部署」區（含四步條） → 頁尾。搜尋涵蓋兩區。 | `mockups/首頁.html` |
| **自助部署**（`/deploy/`，將取代 `/grade-deploy/`） | 登入前：會做／不會做、登入。登入後：我的系統（產品卡、已安裝清單、首次安裝／更新）。首次安裝四步：開始前、確認、安裝中、完成後設定。更新四步：選擇專案、檢查結果、確認更新、完成。另有兩個例外畫面：平台尚未開放（後端未設定）、登入後沒有任何授權（模擬頁畫面 1、3）。 | `mockups/自助部署.html` |
| **GAS 工具預覽頁**（`/gas/<工具 id>/`，每個「施工中・可預覽」的工具一頁） | 導覽 → 麵包屑 → 小標、工具名稱、一句話 → 狀態橫幅 → 「主要功能」與「為什麼要部署到 GAS」兩個面板 → 「上線前的檢查」四項進度 → 「← 返回 GAS 部署區」 → 頁尾。細則見 5.1。 | `mockups/GAS工具預覽頁.html` |
| **部署管理**（`/deploy/admin/`，將取代 `/admin/`） | 四個分頁：教師授權、正式版、部署紀錄、稽核紀錄。教師授權用勾選矩陣；正式版審核必須表態「是否涉及資料遷移」。部署紀錄與稽核紀錄沿用表格元件。 | `mockups/部署管理.html` |

自助部署與管理頁是**前端介面**，原始碼在本 repo 的 `deploy/`，實作指引在 `docs/deploy/`（含精靈的規範）；它們呼叫的**後端**（授權閘門、教師白名單、正式版發布包）與安裝、更新的安全規則在私人 repo `derliang/gas-deploy-helper`。本文件只規定外觀：色彩與字型一律以 `tokens.css` 為準，通過 `check_design.py` 才能合併（見 PAGES.md 第 7 節）。

### 5.1 未完成的 GAS 工具怎麼呈現

GAS 工具在通過真實驗收前，只有兩種合法呈現。**不得用別的樣子暗示它能用。**

| 狀態 | 首頁卡片 | 點下去 | 說明頁 |
|---|---|---|---|
| 候選 | `<article>`，虛線外框、透明底、圖片轉灰；狀態標籤「候選」；版本欄寫「尚未推出」；底部「敬請期待」 | 不可點，沒有連結 | 不需要，也不得建立 |
| 施工中・可預覽 | `<a>`，黃銅外框；狀態標籤「施工中・可預覽」；版本欄寫「尚未發布」；底部「進入預覽」或「進入自助部署」 | 連到該工具的預覽頁 `gas/<id>/`；過渡期的平時成績連舊原型 `grade-deploy/` | GAS 工具預覽頁（下表） |

候選要變成可點，必須先建好預覽頁並改標「施工中・可預覽」；卡片與預覽頁要在同一個 PR 內。候選卡不可用「候選」標籤加上連結。

**預覽頁規則**（版型見 `mockups/GAS工具預覽頁.html`）：
- 路徑 `gas/<工具 id>/index.html`，登記在 `pages.json`（已有 `gas/*/index.html` 的樣式規則），麵包屑為 `Teacher Hub 首頁 › GAS 部署 › 工具名稱`。
- 狀態橫幅固定寫「**施工中**｜目前僅供預覽介面，尚未開放 Google 登入、GAS 安裝或更新。」不寫日期、不寫「即將上線」。
- 內容只放：這個工具做什麼（沿用首頁卡片的一句話與功能詞）、為什麼要部署到 GAS（多人同時使用、程式安裝在老師自己的 Google 帳號）、上線前的四項檢查進度（核准進入自助部署、正式版通過審核並確認資料相容、管理員開通教師帳號、通過真實環境驗收）。
- **不得有**：任何 `<button>`、Google 登入或授權、假的安裝或更新流程、假的使用者資料。這一條由 `check_design.py` 強制檢查。
- 一定要有「← 返回 GAS 部署區」，連到首頁 `#gas`。
- 轉正式：通過第 4 項驗收、擁有者說「發佈網頁」後，刪除該預覽頁與 `pages.json` 的對應，卡片改連 `deploy/?product=<id>` 並標「即開即用」。

**平台自身的未完成狀態**（`/deploy/` 已上線但功能還沒就緒）：
- 平台後端未設定：顯示「平台尚未開放」警示（warn），保留「會做／不會做」說明，沒有登入面板。
- 登入後沒有授權：顯示「你的帳號（…）還沒有任何系統的使用授權，請把這個 Email 告訴管理員」。
- 產品沒有已核准的正式版：安裝與更新按鈕停用，並說明「目前沒有已核准的正式版，暫時無法安裝或更新」。

### 5.2 每一層的導覽

子頁（`/deploy/`、`/deploy/admin/`、`gas/<id>/`）頂端導覽的「立即可用」「GAS 部署」連結指向首頁錨點（`../#usable`、`../#gas`，管理頁為 `../../#usable`、`../../#gas`），品牌連到首頁；「GAS 部署」為目前項目。

任何新頁面都要在 PAGES.md 第 2、4 節找到自己的層級，並具備該層必備的導覽（頂端導覽、麵包屑、返回連結、頁尾）。沒有麵包屑的子頁、沒有返回連結的預覽頁，一律不得合併。

## 6. 文案語氣

- 台灣繁體中文，直述句，對老師說話。用「你」，不用「您」，不用感嘆號。
- 按鈕寫出會發生的事：「開始安裝」「更新到新版」，不寫「確定」「提交」。
- 錯誤訊息寫「發生什麼事、下一步怎麼做」，不道歉、不含糊。
- 狀態要誠實：寫「施工中」「尚未推出」，不寫「即將上線」暗示日期。
- 工具說明：第一句講它幫老師做什麼；特色列只放該工具原有的功能詞，不寫尚未存在的功能。
- 不用 emoji 當標示，用文字標籤與符號（✓、✕、›、→、↗）。

## 7. 無障礙

- 文字對比至少 4.5:1（大標題 3:1），淺深色兩套都要過；前景用不透明色，不用透明度把字變淡。
- 點擊區至少 44px；焦點框可見；整張卡片連結要有 `aria-label`。
- 資訊不只靠顏色：狀態同時有文字標籤。
- 圖片有替代文字；不得含真實學生個資。
- 麵包屑用 `<nav aria-label="所在位置">`，目前頁用 `aria-current="page"`；導覽目前項目用 `aria-current`。

## 8. 不要做的事

- 不使用大圓角、膠囊標籤、卡片左側色條、漸層背景、emoji 標示、置中對齊的大段落。
- 不在元件裡寫死色碼或字型；不新增第三種強調色。
- 不把工具卡改成需要點兩次才能開啟，不用 iframe，不搬移或重新部署原工具。
- 不在首頁放真實學生、教師或授權名單資料；模擬頁只用假資料（例如 `teacher01@example.edu.tw`）。
- 不替未驗收的功能做出「可以用」的樣子。
- 不移除或改寫頁尾版權句與授權連結。
- 不新增沒有登記在 `pages.json` 的頁面；不複製別頁的 CSS 再改色；不新增例外頁（舊風格過渡頁只會減少）。
- 不為了讓檢查通過而修改檢查或 `tokens.css`；真的要改，先更新本文件並取得擁有者確認。
- 偏離本文件前先更新本文件並取得擁有者確認，不要只改程式。
